Axiom Program Validation Architecture

Target split for encoding, runtime execution, and external oracle comparison across Axiom, PolicyEngine, TAXSIM, PRD, and ACCESS NYC.

Design center Thin concept interface, many engine adapters

Target Architecture

What Lives Where

axiom-corpus

Legal source material.

  • Source sections and citations
  • Jurisdiction metadata
  • Versioned source text

axiom-rules

RuleSpec execution layer.

  • RuleSpec compiler
  • Runtime execution
  • Compiled artifacts and test runner

axiom-programs

Executable program validation.

  • Thin concept-keyed case schema
  • Adapters for PE, ACCESS NYC, PRD, TAXSIM, Axiom
  • eCPS and synthetic sweeps
  • Comparator, tolerances, report JSON

axiom-encode

Agentic encoding workflow.

  • Prompts and task orchestration
  • Eval-suite manifests
  • Reviewer gates and telemetry
  • Calls oracle comparisons, but does not own them

Comparison Modes

Mode Example Owned By Output
Encoding-time oracle Axiom RuleSpec companion test vs PolicyEngine variable axiom-encode calling axiom-programs Pass rate, coverage, reviewer context
Dataset parity Axiom vs PE over eCPS axiom-programs Record-level mismatches and aggregate deltas
External oracle parity PE vs ACCESS NYC for SNAP, Medicaid, Essential Plan axiom-programs Eligibility disagreements by scenario
Static rule audit ACCESS NYC Drools thresholds and program-code drift axiom-programs Findings with file and line references
Multi-way validation Axiom vs PE vs ACCESS NYC axiom-programs Consensus, outlier engine, suspected source of drift

Migration Plan

1

Stabilize the harness

  • Keep the adapter interface small and concept-keyed.
  • Finish ACCESS NYC mapper, API runner, and static audits.
  • Separate case suites from concept/program selection.
  • Preserve JSON and CSV report formats from the start.
2

Move shared PE pieces

  • Move PE registry and adapter metadata from axiom-encode.
  • Keep axiom-encode as a caller during the transition.
  • Retain legal-ID based lookup for RuleSpec tests.
3

Wire dataset parity

  • Promote the current PE eCPS benchmark into a true comparator.
  • Add Axiom runtime replay over the same cases.
  • Report record-level and weighted aggregate gaps.
4

Unify external oracles

  • Wrap TAXSIM and PRD packages as adapters.
  • Add ACCESS NYC credentials and synthetic sweep support.
  • Emit reports for PE vs ACCESS NYC and Axiom vs PE vs ACCESS NYC dashboards.

If starting from scratch

Build axiom-programs first as a thin adapter and comparison library, then let axiom-encode depend on it. That avoids encoding workflow code becoming the permanent home for PE, TAXSIM, PRD, ACCESS NYC, and eCPS mechanics.

Boundary to protect

axiom-encode should answer whether agents can produce good RuleSpec. axiom-programs should answer whether executable policy engines agree.
